## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

同一个服务在不同环境下要读不同的配置，而现在这套优先级逻辑散落在各个类里，谁也说不清到底哪份生效。请从零实现一个配置加载与校验库，仓库目前是个空的 Maven 工程，只声明了 JUnit 5 与 AssertJ。要求：1) 支持四种配置来源，优先级由低到高为：代码内默认值 < 配置文件（Properties 或 YAML 任选其一） < 环境变量 < 启动参数；高优先级覆盖低优先级，需有测试逐层验证覆盖关系；2) 类型转换：把字符串配置转为基本类型、枚举、时长（如 30s、5m）、文件路径、逗号分隔列表；转换失败必须给出「配置键 + 期望类型 + 原始值」的明确错误；3) 校验：实现 `@Required`、`@Range`、`@Pattern` 三个自研校验注解，校验失败时一次性汇总全部问题而不是只报第一个；4) 错误定位：配置文件格式有误时必须报出文件路径、行号与原因；5) 结构映射：支持把配置映射到嵌套配置类（含嵌套对象与列表），字段名到配置键的转换规则由你定义并写入 README；6) 动态刷新：配置文件变化时重新加载并通知监听器，刷新失败时保留旧配置并报告错误；7) `mvn -q verify` 跑通全部测试；8) README 说明优先级设计、类型转换规则、校验注解用法与已知限制。
